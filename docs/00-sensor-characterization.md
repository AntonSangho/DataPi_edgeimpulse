# Phase 0 — BH1750 센서 특성 측정

> 상태: **측정 대기** — `mpremote run src/characterize.py` 실행 후 결과를 채워 넣을 것

## 왜 이걸 먼저 하는가

*AI at the Edge* Ch.6 "Determining Feasibility → Technological Feasibility"의 요지는
**모델을 만들기 전에 센서가 그 현상을 담을 대역폭과 민감도를 가졌는지부터 확인하라**는 것이다.
조도 센서로 손동작을 구분하려면 두 가지가 성립해야 한다.

1. **시간 해상도** — 제스처(0.3~1초)를 여러 샘플로 쪼갤 만큼 빨라야 한다. 최소 20~25 Hz.
2. **진폭 분리도** — 손동작에 의한 lux 변동이 `idle`의 잡음보다 뚜렷하게 커야 한다.

둘 중 하나라도 안 되면 클래스 정의나 창 길이를 바꿔야 하고, 그 판단은 데이터를 수백 개
모으기 **전에** 내리는 편이 싸다.

## BH1750 변환 시간 (데이터시트)

연속 모드 변환 시간 ≈ `base × (MTreg / 69)`

| 해상도 | base | MTreg=31 | MTreg=69 | 분해능 |
|---|---|---|---|---|
| H-Resolution (0) | 120 ms | ~54 ms (18 Hz) | ~120 ms (8 Hz) | 1 lx |
| L-Resolution (2) | 16 ms | ~7 ms (139 Hz) | ~16 ms (63 Hz) | 4 lx |

→ 이론상 **L-Resolution + MTreg=31**이면 25 Hz는 여유롭게 나온다.
분해능 4 lx가 문제되는지가 관건이고, 그건 아래 동적 범위 측정으로 판단한다.

lux 환산은 `raw / (1.2 × (69 / MTreg))`이므로 MTreg를 줄이면 같은 밝기에서 raw 카운트가
커진다 — 즉 짧은 측정시간은 밝은 환경에서 포화(65535)에 가까워질 수 있다. 밝은 창가에서도
포화되지 않는지 함께 확인한다.

### 조정 규칙 (계획 문서의 "열린 항목")

- 25 Hz가 안 나오면 → 샘플레이트를 실측치로 낮추고 **창 길이를 늘려 샘플 수(50개)를 유지**한다.
- `swipe`가 `wave`와 분리되지 않으면 → `swipe`를 빼고 3-class로 축소한다. 판단은 Phase 2 혼동행렬에서.
- 밝은 환경에서 포화되면 → MTreg를 키우거나 (샘플레이트 희생) H-Resolution으로 바꾼다.
